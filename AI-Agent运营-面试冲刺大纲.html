AI Agent 运营 · 面试冲刺大纲

江苏觅听（A轮）· 南通崇川区 · 4–6K · 1年以内 · 大专

初级 / 实习岗 重落地，不考算法 Python 够用即可 今晚 4 小时可突击

先看清这场面试的底层逻辑

  • 岗位是「运营」，不是「算法工程师」。 4–6K、大专、1年以内，说明他们要的是能马上上手配 Agent、写 Prompt、测效果、看数据的人。Python 只是工具，不是考点。
  • 你会 Python 和 LLM 只是加分项，运营思维才是主线。 面试官更怕招来一个只会跑 demo、不会对结果负责的人。
  • 竞争很激烈（平台显示你已超过部分竞争者）。 差异化只有一个：拿出「我已经做过」的证据——一个跑通的脚本、一个搭过的 Agent、一份 Prompt 模板库截图。

01面试流程与时间分配先知道会发生什么

  • 自我介绍（1–2 分钟）
    HR 或业务负责人开场，决定第一印象，必须背熟。
  • 岗位理解 + 动机（5 分钟）
    为什么选 AI 运营？为什么是我们公司？能不能干长久？
  • AI / 大模型认知（10–15 分钟）
    概念题为主，考「是否真的用过」，不考推导。
  • Python 动手能力（5–10 分钟）
    大概率让你讲一段代码，或问「能不能写个脚本调 API」。
  • 运营方法论 + 场景题（10–15 分钟）
    给一个业务场景，让你设计 Agent 或分析数据。
  • 稳定性 / 实习时间 / 薪资（5 分钟）
    每周能到岗几天、能实习多久、期望薪资。
  • 你的反问（2–3 分钟）
    问得好能显著加分，见第 07 节。

02自我介绍模板直接背，30 秒版 + 90 秒版

结构：我是谁 → 我和这个岗位的三个连接点 → 我能马上做什么。不要流水账，不要背简历。

30 秒版（HR 初面用）

您好，我是南通理工 XX 专业的学生，目前可实习。我关注 AI Agent 运营这个方向，是因为我平时就在用扣子 / Dify / 豆包这类工具搭智能体，也自己写过调用大模型 API 的 Python 脚本。我的优势是上手快、愿意做脏活——搭 Agent、写 Prompt、整理 badcase 这些事我能立刻分担。希望有机会在贵司系统地把这件事做深。

90 秒版（业务负责人面用）

在 30 秒版基础上，补一个具体例子：「我之前用 XX 工具搭过一个 XX 场景的 Agent，遇到的最大问题是 XX，我是这样解决的 XX，最后效果是 XX。」 这个例子是整场面试的锚点，后面所有问题都往它上面靠。

没有项目怎么办？ 今晚花 40 分钟现做一个：用扣子 / Dify 搭一个「XX 咨询助手」，接一个知识库，截图存手机。明天就有得讲。没有证据的「我学习能力强」等于没说。

03大模型核心概念卡片能用自己的话讲出来即可

下面 12 张卡是这类岗位的「认知及格线」。不要背定义，要能说出它解决什么问题、什么时候用。

Token

模型处理文本的最小单位，中文约 1 字 ≈ 1–1.5 token。计费、上下文长度、响应速度都按它算。

上下文窗口

模型一次能「看到」的 token 上限。超了要截断或做摘要。越长越贵、越慢，不是越大越好。

Temperature

控制随机性，0–2。低（0–0.3）稳定适合客服/抽取；高（0.7+）发散适合创意。做 Agent 通常调低。

幻觉 Hallucination

模型一本正经地编造事实。缓解手段：RAG 给资料、Prompt 约束「不知道就说不知道」、工具查询、人工兜底。

Prompt 工程

公式：角色 + 任务 + 约束 + 示例（Few-shot）+ 输出格式。复杂任务加「一步步思考」（CoT）。

RAG 检索增强

文档切块 → 向量化（Embedding）→ 存向量库 → 按问题召回 → 拼进上下文生成。解决私域知识、时效性问题。

微调 Fine-tuning

用标注数据改模型行为/风格。成本高、周期长；适合固定风格与格式，不适合天天变的知识。

Function Calling

模型输出结构化的「我要调用哪个工具、参数是什么」，程序执行后把结果回传。Agent 能查天气、查订单、发邮件全靠它。

Agent

大模型 + 规划 + 记忆 + 工具 + 循环。ReAct：思考 → 行动 → 观察 → 再思考，直到完成任务。

Workflow vs Agent

Workflow 是固定流程编排（稳、可控、便宜）；Agent 是自主决策（灵活、但易跑偏、贵）。运营要先问：这个场景真需要自主决策吗？

MCP

Model Context Protocol，把模型和外部工具/数据源标准化连接。一句话：让「接工具」变成插拔式。

效果评估

任务完成率、准确率、幻觉率、响应时延、单次成本、人工介入率、用户满意度。运营的核心工作之一就是建 badcase 库。

Agent 运行流程（画得出来就赢一半）

用户输入→ 意图理解 / 规划→ 选择工具 / 检索知识库→ 执行 & 观察结果→ 生成回答→ 兜底 / 转人工

被问「设计一个 Agent」时，就按这条链子讲，并补上「每一步的失败情况怎么处理」——这是运营和技术的区别。

04Python 最小可用集只学能写脚本的部分

必须会（今晚过一遍）

主题要点
数据结构list / dict / tuple / set 的增删改查；dict 取值用 get() 防 KeyError
控制流 & 函数if / for / while；默认参数、*args、**kwargs；返回值
文件 & JSONopen(..., encoding="utf-8")；json.load / json.dump

这段代码要能默写并讲清每一行

# 调用大模型 API —— 面试高频，能讲清就是「真用过」
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["OPENAI_API_KEY"],   # 从环境变量读，不硬编码
    base_url="https://api.xxx.com/v1"         # 国内模型一般要改 base_url
)

resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "你是电商客服，只回答退换货问题。"},
        {"role": "user",   "content": "买的衣服能退吗？"},
    ],
    temperature=0.3,      # 客服场景要稳
)
print(resp.choices[0].message.content)

会被追问的点：messages 里 role 有哪几种？（system / user / assistant / tool）· 为什么要传 system？（设定角色与规则）· 怎么控制输出 JSON？（Prompt 里给 schema + 用 response_format 或让模型输出后 json.loads）

Python 高频八股（初级只会问这些）

list 和 tuple 区别？ 可变 vs 不可变，tuple 更省、可作 dict 的 key。

深拷贝浅拷贝？ 浅拷贝只复制第一层，嵌套对象还是共享引用；深拷贝用 copy.deepcopy。

可变默认参数的坑？ def f(a=[]) 的列表会在多次调用间累积，应写 a=None 再判断。

装饰器是什么？ 不改原函数代码、给它套一层额外逻辑（如计时、重试），基于闭包。

生成器？ 用 yield 逐个产出，省内存，适合处理大文件。

05运营方法论 + 数据这才是岗位主线

AARRR 是什么？怎么用到 Agent 产品？

获取 → 激活 → 留存 → 变现 → 推荐。落到 Agent：获取=渠道投放/内容引流；激活=用户完成第一次有效对话；留存=7 日内再次使用；变现=付费/订阅；推荐=分享裂变。

Agent 的回答质量怎么评估？

四层：① 建评测集（覆盖高频 + 边界问题）；② 人工按维度打分（准确性、完整性、语气）；③ 用大模型当裁判（LLM-as-judge）批量跑分；④ 线上看任务完成率、转人工率、差评率，把 badcase 沉淀成回归测试集。

怎么判断一次改版有效？

A/B 测试：只改一个变量（如 Prompt 版本），分流用户，看核心指标（完成率/留存）差异是否显著，避免用「感觉变好了」下结论。

北极星指标怎么定？

找「用户获得价值」的那个数。客服 Agent 是自助解决率；内容 Agent 是有效产出采纳率；不是 DAU 这种虚荣指标。

运营岗的杀手锏回答：「我会先定义什么叫『好』，再用数据证明它变好了，最后把有效的做法固化成 SOP / 模板。」——这句话能同时打动技术面和业务面。

06场景题万能框架大概率现场出题

题目长这样：「如果让你给我们做一个售前咨询 Agent / 招聘筛选 Agent / 内容生成 Agent，你怎么做？」

按这 8 步讲，先讲骨架再补细节，不要一上来就讲技术：

  • ① 目标与指标
    这个 Agent 要替谁解决什么问题？成功指标是什么？
  • ② 用户与场景
    谁用、在什么渠道用、最高频的三个问题是什么。
  • ③ 能力边界
    哪些它做、哪些必须转人工——边界先划清。
  • ④ 知识来源
    产品文档、FAQ、历史聊天记录 → 清洗入库（RAG）。
  • ⑤ 流程与工具
    意图识别 → 检索 → 调工具（查库存/下单）→ 生成 → 兜底。
  • ⑥ Prompt 设计
    角色、语气、必须遵守的规则、禁止事项、输出格式。
  • ⑦ 评测与上线
    先小流量灰度，建 badcase 库，按周迭代 Prompt 与知识库。
  • ⑧ 复盘
    用数据说话：解决率、满意度、成本，再决定加功能还是砍功能。

07行为面 & 反问决定「要不要你」

为什么想做 AI Agent 运营？

别说「因为 AI 火」。说：「我喜欢把不确定的东西跑通——搭一个 Agent、看它从答错到答对，这个过程让我有成就感；而且运营能直接看到用户反馈，迭代最快。」

你最大的缺点？

说一个真实但不致命的：「工程底子不深，复杂的后端我搞不定，所以我会把边界内的脚本和配置做扎实，遇到搞不定的及时问。」 别用「我太追求完美」这种套路。

能实习多久？一周几天？

这是他们的核心顾虑。给明确数字：「一周可到岗 X 天，能稳定实习 X 个月以上。」含糊会被扣分。

期望薪资？

岗位写 4–6K，实习通常按天算。「按公司实习标准来，我更看重能接触真实业务和转正机会。」 先问清实习补贴与转正机制，别先报数。

加分反问（挑 2–3 个问）

① 团队现在主要做哪类 Agent？我入职第一个月具体负责什么？

② 目前 Agent 的效果怎么评估？badcase 是怎么流转和复盘的？

③ 这个岗位做得好的话，半年后是什么样子？有转正 / 带教机制吗？

④ 现在最大的瓶颈是模型能力、数据，还是用户不知道怎么用？

08今晚 4 小时冲刺清单按顺序做，别贪多

  • 40 min｜查公司：搜「江苏觅听」，看官网、公众号、招聘页、产品截图，搞清楚它卖什么、客户是谁。面试里提一句产品细节，直接碾压竞争者。
  • 60 min｜背概念卡：把第 03 节 12 张卡盖住解释，用自己的话讲一遍，讲不出的做标记再背。
  • 50 min｜跑通代码：照第 04 节把脚本敲一遍（有 key 就跑，没有就讲清每行）。顺便练一个「读 CSV 统计 Top10」的 pandas 小题。
  • 40 min｜做个小 Agent：用扣子 / Dify 搭一个简单场景，截 2–3 张图存手机，作为「证据」。
  • 30 min｜练自我介绍：掐表 90 秒，录音回听，去掉「然后、就是、那个」。
  • 20 min｜过反问 + 薪资：把第 07 节的话术说顺，避免现场卡壳。

09五个必须避开的雷区

① 别把「运营岗」当「算法岗」准备。 背 Transformer 公式没用，会被问「那你具体做过什么」问穿。

② 别吹 Python。 说「会写脚本、能调 API、能处理数据」就够，吹大了现场写不出 for 循环直接出局。

③ 别说「我是来学习的」。 换成「我能马上分担 XX 工作，同时在 XX 上快速补」。公司要的是产出，不是学生。

④ 别只谈技术不谈业务。 每个技术点后面都接一句「所以对用户/指标意味着什么」。

⑤ 别对加班、实习时长含糊。 小公司最怕招来干两周就走的人，态度要明确、务实。
